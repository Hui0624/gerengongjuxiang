# 飞书提醒

工作台课程 / 待办的飞书推送。放在 Cloudflare Worker 上跑，**跟手机开不开、工作台开不开都无关**。

## 它什么时候发

| 触发 | 时间 | 内容 |
|---|---|---|
| 上课 | 开课前 30 分钟 | 课名、时间、地点、老师 |
| 待办（填了时间的） | 到点前 30 分钟 | 待办内容 |
| 早间汇总 | 每天 07:30 | 今天几节课、几件待办（**覆盖没填时间的待办**） |
| 晚间提醒 | 每天 20:30 | 今天还有几件没勾 |

课程会先按 `weeks` 周次过滤，只发「这周真的上」的课。教务导入的 50 条课里，同一时段常有好几条（不同周次 / 实验分组），不过滤的话一次会推 4 门。

## 文件

| 文件 | 作用 |
|---|---|
| `worker.js` | Cloudflare Worker 全部逻辑，自包含，可直接粘进后台 |
| `local-test.js` | 本机预览 / 真发，用来验证 |
| `secrets.json` | 你的 webhook / token / gistId。**已在 .gitignore 里，不会进公开仓库** |

## 本地验证（现在就能跑）

```bash
node 飞书提醒/local-test.js --scan          # 看今天该上什么课、几点会提醒
node 飞书提醒/local-test.js --at 18:30      # 模拟 18:30 这一刻，看会发什么
node 飞书提醒/local-test.js --at 18:30 --send   # 真发到飞书
node 飞书提醒/local-test.js --date 2026-11-10 --scan   # 看明天
```

`--scan` 是验证周次解析最直接的办法：如果列出来的课跟你实际课表对不上，说明 `weeks` 字段解析有问题，别急着部署。

## 部署到 Cloudflare（约 10 分钟，全程免费）

**1. 注册**
打开 https://dash.cloudflare.com/sign-up ，邮箱 + 密码即可，不用绑卡。

**2. 建 Worker**
左侧 `Workers & Pages` → `Create` → 选 `Start with Hello World!` → 名字填 `wb-reminder` → `Deploy`

**3. 贴代码**
进去后点 `Edit code` → 把编辑框里的示例代码**全选删掉** → 粘贴本目录 `worker.js` 的**全部内容** → 右上角 `Deploy`

**4. 加三个密钥**
Worker 页面 → `Settings` → `Variables and Secrets` → `Add`，一条一条加，类型都选 **Secret**：

| 变量名 | 值 |
|---|---|
| `FEISHU_HOOK` | 飞书群机器人 webhook 地址 |
| `GH_TOKEN` | 只勾了 gist 权限的 GitHub token |
| `GIST_ID` | `93cbeee886825280bb022f50d0e46117` |

加完点 `Deploy` 让它生效。

**5. 设每分钟触发**
`Settings` → `Trigger Events` → `Cron Triggers` → `Add`，填：

```
* * * * *
```

保存。

**6. 验证**
浏览器打开你这个 Worker 的地址（形如 `https://wb-reminder.xxx.workers.dev`），会返回一段 JSON：

```json
{
  "现在": "2026-11-09 周一 第 11 周 14:23",
  "这一刻会发": [],
  "今天的课": ["10:00 大学体育Ⅲ-定向越野", "19:00 具身智能机器人控制技术"],
  "今天的待办": ["未定时间 申报书"]
}
```

`今天的课` 跟你实际课表一致 → 周次算对了。这个地址只干跑，不会真发消息。

想验证真的会推：等一个整点前 30 分钟（比如 18:30 有课），或者把 `LEAD_MIN` 临时改成 0 再改回来。

## 可选变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `LEAD_MIN` | 30 | 提前几分钟 |
| `MORNING_AT` | `07:30` | 早间汇总时间，设 `off` 关闭 |
| `EVENING_AT` | `20:30` | 晚间提醒时间，设 `off` 关闭 |

## 出问题怎么查

| 现象 | 原因 | 解法 |
|---|---|---|
| 飞书返回 `19021` | 消息里没有「自定义关键词」 | 机器人安全设置里的关键词必须是 `工作台`，代码里 `【工作台】` 前缀就是干这个的 |
| 飞书返回 `11232` | 限流（100 次/分钟） | 正常不会碰到；偶发在整点整分 |
| 读 Gist 返回 `401` | token 过期或没勾 gist 权限 | 重新生成 token，只勾 `gist` |
| 读 Gist 返回 `404` | `GIST_ID` 写错 | 打开 gist.github.com 复制网址最后那段 |
| 课表对不上 | 周次解析问题 | 跑 `--scan` 对照真实课表 |
| 某天完全没提醒 | 那一分钟 Worker 没跑起来 | Cloudflare 免费版不保证 100%，极偶发 |

## 已知限制（说清楚，不糊弄）

1. **靠「正好差 30 分钟」那一分钟触发**，所以不需要去重表，也不会重复发。代价是那分钟如果没跑起来就漏了。
2. **待办必须填时间**才有到点提醒。没填时间的只能靠 07:30 的早间汇总兜底——你现在 9 条待办全都没填时间。
3. **假期不识别**。填了课表周次才会跳过，没填周次的课每周都会响。
4. **webhook 泄露了要立刻重置**（飞书机器人详情页可以重置地址），否则别人能给你发垃圾消息。

## 安全

- `secrets.json` 不进 git，但**它现在就在这台电脑的明文里**，别把它传到任何公开的地方
- 更稳的做法：GitHub token 只勾 `gist` 一项，就算泄露也动不了你的仓库代码
